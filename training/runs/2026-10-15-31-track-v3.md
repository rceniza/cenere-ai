# 2026-10-15: 31-track curriculum and code-generation candidate

## Data and setup

- Curriculum: 31 tracks, 287 lessons, with 93 supervised explanations and 31 validation examples.
- Code training split: nine verified source answers for C, C++, PHP, JavaScript, TypeScript, Node.js, Python, Rust, and Go; 31 held-out rubric prompts and nine held-out executable code prompts.
- Model: local Qwen2.5-Coder-3B-Instruct-4bit on Apple M3 with 24 GB unified memory.
- Candidate: 10 MLX LoRA iterations, batch size 1, one trainable layer, sequence limit 512; validation loss was 5.102 at iteration 1 and 4.548 at iteration 10. Training completed with the base server running; system free memory was 54% before the run and 48% during evaluation.

## Results

| Measure | Base | Candidate |
| --- | ---: | ---: |
| Held-out keyword rubric | 5/31 | 5/31 |
| Executable code benchmark | 0/9 | 0/9 |

The candidate was not promoted. Its rubric score matched the base and none of its generated programs passed the shared seven-case behavior suite. The base also scored 0/9. Failures included wrong-language source inside a valid code fence, undeclared dependencies, extra stdout, invalid parsing, and incorrect error handling. These results show that the current code-training set is too small and too repetitive to teach reliable code generation. Training loss is not an answer-quality measure.

## Coverage boundary and next work

The v1 explanations now span 31 broad tracks, including legacy systems and modern framework families. The nine executable references remain one narrow command-line exercise per language; they do not train framework, database-engine, mobile, or infrastructure implementation. Expand those code examples with distinct tasks and stack-specific executable or configuration checks, then repeat the same held-out comparison. Do not spend longer training runs on this corpus until those examples improve.

The 31-track rubric is a keyword screen, not a semantic correctness test. The executable suite is stronger for the specific command-line task but does not establish general coding ability. The output files used for evaluation are temporary under `/tmp` and are not committed.
