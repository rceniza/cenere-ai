# Local training and evaluation run · 2026-10-15

## Setup

- Host: Apple Silicon Mac, 24 GB unified memory, 8 logical cores.
- Base checkpoint: local `Qwen2.5-Coder-3B-Instruct-4bit` MLX conversion (1.6 GB on disk; `Qwen2ForCausalLM`, text-only).
- Training data: `train.jsonl` (75 examples); validation: `valid.jsonl` (25 examples); held-out: `eval.jsonl` (25 cases).
- Training command: 10 iterations, batch size 1, one LoRA layer, gradient checkpointing, max sequence length 512, two validation batches.
- Memory pressure: 56% system-wide free before training, 42% immediately after, 37% while base and candidate inference servers ran side by side. The temporary candidate server was stopped afterward; the original base server remained available.

## Results

| Check | Result |
|---|---:|
| MLX-LM dataset load | 75 train / 25 valid |
| Training loss at iteration 10 | 4.503 |
| Validation loss, iteration 1 → 10 | 5.364 → 4.478 (two batches) |
| Base model heuristic rubric | 5 / 25 |
| Candidate adapter heuristic rubric | 4 / 25 |

The rubric score is literal substring coverage plus forbidden-phrase checks, not a semantic correctness metric. The candidate did not improve it and is **not promoted**. Training loss and a two-batch validation loss decrease do not override the held-out result. The base model still made important errors, including describing Go as using `try-catch` and recommending Redis Sentinel as a response to cache outages. The one-layer, ten-step run is too small to establish broad capability improvement.

The candidate adapter remains a local artifact under `training/adapters/cenere-multistack-v1/` and is excluded from Git. Reproduce this short run with the commands in the dataset README. A next training attempt should first improve the task-level evaluation and add executable, stack-specific checks; do not serve this candidate as an upgrade.
